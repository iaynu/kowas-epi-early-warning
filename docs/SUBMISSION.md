# KOWAS-EPI 하수 감시 기반 t+2주 농도·급증 경보 예측 모델 (r2_plant_v7_safe)

2026 DATA·AI 분석 경진대회 「하수 감시 데이터 기반 감염병 유행 조기예측 AI 모델 개발」 **The사랑해팀** 제출 모델입니다.
시·도 17개마다 원점 주차 t까지 공개된 자료만으로 **t+2주 하수 SARS-CoV-2 농도(`pred_conc`)**와 **급증 경보(`pred_alert`)**를 예측합니다.

## 1. 빠르게 실행하기

저장소를 `KOWAS-EPI_model/` 폴더로 받습니다(`git clone <저장소 주소> KOWAS-EPI_model`, 대회 제출본은 모델자료 zip을 풀면 같은 폴더가 생깁니다). 아래 예시는 KOWAS-EPI v2.5 배포 폴더(`evaluation.py`가 있는 곳)에서 실행하며, `KOWAS-EPI_model/`을 그 옆(`../KOWAS-EPI_model/`)에 두었다고 가정합니다.

가장 간단한 방법은 `scripts/`를 쓰는 것입니다(환경 설치 후 한 개 평가 창만 실행해 동작을 확인).

```bash
bash scripts/setup_env.sh                                 # .venv 생성 + requirements.txt 설치
bash scripts/run_backtest.sh ~/KOWAS-EPI 2024-Q2          # 평가 창 1개 (약 1분), 결과는 results/ 에 저장
bash scripts/run_backtest.sh ~/KOWAS-EPI                  # 전체 10개 창 (약 20~35분)
python scripts/check_predictions.py results/predictions.csv --keys ~/KOWAS-EPI/eval_keys.csv --folds --compare predictions.csv
```

Windows는 같은 이름의 `.ps1` 파일을 씁니다. 스크립트가 만드는 `results/`는 제출본(`predictions.csv`, `score.json`)을 덮어쓰지 않습니다. 아래는 스크립트 없이 직접 실행하는 명령입니다.

```bash
python -m venv .venv
.venv/bin/python -m pip install -r ../KOWAS-EPI_model/requirements.txt
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
.venv/bin/python evaluation.py backtest --model ../KOWAS-EPI_model/model.py \
    --out ../KOWAS-EPI_model/predictions.csv --json ../KOWAS-EPI_model/score.json
.venv/bin/python evaluation.py score ../KOWAS-EPI_model/predictions.csv
```

- Windows는 `.venv\Scripts\python.exe`를 쓰고, 스레드 환경변수는 PowerShell에서 `$env:OMP_NUM_THREADS="1"`처럼 설정합니다.
- `--folds`와 `--keep-going`을 붙이지 않습니다.
- 평가기가 평가 창마다 새 프로세스를 띄우고 `KOWAS_STATIC_DIR`를 배포 폴더로 지정합니다.
- 설치가 끝난 뒤에는 네트워크를 쓰지 않습니다.

## 3. 예측 흐름

원점 주차 t마다 다음 순서로 계산합니다. 모든 단계는 원점 이하의 자료만 씁니다.

1. **입력 정리.** 원점 이후 행과 목표주가 원점 이후인 라벨을 한 번 더 가립니다(평가기의 마스킹을 보강). 결측 주의 3주 평균에 다음 주 값이 섞인 알려진 예외(대구 2025-W04)는 지역·날짜를 지정하지 않고 과거 관측값으로만 다시 계산합니다.
2. **최근 학습기(`core.py`).**
   - **타깃:** 기준값(원점 `conc_3wk_avg`, 없으면 마지막 관측값) 대비 2주 뒤 log10 농도 변화량
   - **모델:** 학습 기간 78·104·26·39주의 Huber 릿지 6종을 가중 평균합니다. 일부는 t+1주 정답으로 학습하고, 일부는 오차에 상한이 있는 sMAPE 모양 손실로 다시 맞춥니다.
   - **보정:** 상승·하락 비대칭, 전국 확산, 학습기간 간 의견 차이 감쇠, 작년 같은 시기 변화, 상황별 변화 폭 조정을 적용합니다.
3. **장기 학습기(`diversity.py`).** 평가 창 시작 때까지의 모든 라벨로 한 번 학습합니다. 처리장 수가 많고 처리장 수 변화가 작을수록 최근 학습기 예측에 더 많이(최대 30%) 섞습니다.
4. **온라인 오차 보정(`online.py`).**
   - 과거 원점마다 그 당시 정보만으로 예측을 다시 만들고, t+2 정답이 이미 관측된 표본만으로 최근 26주의 오차 보정기를 학습합니다.
   - 사용하는 특징은 최근·직전·4주 평균 오차, 전국 평균 오차, 변동성이고, 강한 정규화(500)를 걸고 보정 비중은 0.25입니다.
5. **경보 임계값 학습(`calibration.py`).** 최근 13개 발행 주의 과거 경보 여유값과 이미 관측된 경보 정답으로, 부드러운 기대 Macro-F1이 가장 높은 임계값을 고릅니다. 0에서 멀어지는 만큼 벌점을 줍니다.
6. **처리장 구성 보정(`plant_bias.py`).**
   - 그 주의 `n_sites`, `pop_sampled`를 `plant_meta.csv`의 처리인구와 대조해, 어느 처리장이 채취됐는지 추론합니다.
   - 처리장 구성이 바뀔 때의 농도 편향을 최근 104주의 관측 변화로 학습합니다. 이때 같은 시기의 전국 변화는 빼서, 유행 자체의 변화와 구분합니다.
   - 앞으로의 구성은 최근 13주의 최빈 구성과 평균 구성을 섞어 예상합니다. 경보에는 평균 구성을 씁니다.
7. **상태 공간 결합(`state_space.py`).** 지역 상태, 감쇠 추세, 처리장 편향을 칼만 필터로 분리한 예측을 처리장 수에 따라 2.5~20% 섞습니다.
8. **학습 이력 안전장치(`model.py`).**
   - 원점까지 쌓인 주차가 26주 이하이면 공식 기준 모델(원점 3주 평균, 현재 경보 지속)을 그대로 씁니다.
   - 50주 이상이면 위 예측을 그대로 쓰고, 그 사이는 로그 농도를 선형으로 섞습니다. 경보는 비중이 큰 쪽을 따릅니다.
   - 공식 평가 창은 가장 이른 원점도 이력이 51주라 작동하지 않습니다(5.1절).

## 4. 자료 처리

### 4.1 결측치

| 상황 | 처리 |
|---|---|
| 그 주 `conc_mean` 결측 | 마지막 관측값을 이어 쓰고 경과 주수·결측 표시를 변수로 둔다. 혼합4 보정값(직전 관측 8개 지수가중 + 전국 변화, 관측 시·도 12개 이상일 때만, 8주 초과 공백은 채우지 않음)은 보정량·보정 신뢰도 변수로만 쓴다 |
| 결측 신뢰도 | 최근 8주 관측 비율, 공백 길이, 최근 4주 결측률을 변수로 넣는다 |
| `conc_3wk_avg` 결측 | 마지막 관측값을 기준값으로 쓴다 |
| `conc_base_avg` 결측 | 최근 4주 관측 평균으로 계산하고, 관측이 2개 미만이면 경보 0 |
| 관측 이력이 없는 시·도 | 다른 시·도 기준값의 평균으로 예측 |
| 강수·신고수 결측 | 0(변화 없음)으로 둔다 |
| 학습 표본 | 2주 뒤 정답이 없는 행은 뺀다. t+1주·t+3주를 쓰는 보조 정답은 그 주가 원점 이하로 관측된 표본에만 쓴다 |

### 4.2 이상값

- **지우거나 잘라내지 않습니다.** 극단값의 영향만 줄입니다.
- 농도를 log10으로 바꾸고 기준값 대비 변화량을 예측합니다.
- Huber 손실을 쓰고, 일부 모델은 오차에 상한이 있는 |tanh| 손실로 다시 맞춥니다.
- 릿지 규제를 걸고, 보정량·계절 변화·온라인 보정에는 상한을 둡니다.
- `wow_change_rate`는 기간별로 부호 규약이 달라 쓰지 않습니다.

### 4.3 주요 변수

최근 수준·변화, 26주 중앙값 대비 수준, 결측 표시, 전국 상대 수준, 강수(패널 주간값과 ASOS 일자료), 전국 신고수 변화, 52주 수준, 처리장 수, 계절성(주차의 sin·cos), 변동성, 경보기준 대비 수준, 시·도 간 변화 분산, 지역 특이 변화, 결측 신뢰도, 전국 확산(2주 사이 2배 넘게 오른 시·도 비율).

변수 구성 시험에서 점수 기여가 가장 컸던 묶음은 계절성, 전국 신고수, 강수, 전국 확산 순이었습니다.

### 4.4 강수 희석

- **입력:** 패널의 시·도 주간 강수(이번 주, 최근 2주 평균)는 최근 학습기의 농도 모델·경보 모델과 LSTM·GRU 시퀀스에 들어갑니다. ASOS 일자료는 관측소-주마다 주 강수 합·일 최대 강수·20mm 이상 일수를 만든 뒤 시·도 안 관측소 평균으로 집계해 장기 학습기에 넣습니다.
- **한계:** 두 자료 모두 시·도 단위 집계라, 실제 하수 집수구역별 강수 노출과 처리장별 희석 차이를 직접 표현하지 않습니다.
- **대회 검정 재현(v2.5, 2,813행):** 지역·계절을 통제한 강수와 그 주 농도 변화의 부분상관 r = −0.0253, 강수와 기온을 함께 더한 R² 증가 +0.000308. 그 주 농도에 대한 선형 분석이므로, 비선형·시차 효과나 2주 뒤 예측 기여가 없다는 뜻은 아닙니다.
- 강수의 실제 예측 기여는 같은 조건의 비교 실험으로 따로 측정했습니다(7.4절).
- 처리장 인근 관측소·실제 하수 집수구역 기반 강수 결합은 현재 모델로 시험하지 않았습니다.

1. 병원체별로 패널을 나눠 하나씩 실행한다. 한 파일에 여러 병원체를 섞으면 안 된다.
2. 같은 열 구성(`conc_mean`·`conc_3wk_avg`·`conc_base_avg`·`n_sites`·`pop_sampled` 등)을 맞추면 코드 수정 없이 재학습만으로 돌아간다.
3. 해당 병원체의 임상 신고수가 있으면 `covid_cases_national` 자리에 넣고, 없으면 비워 둔다.

**한계**
- 혼합 비율·보정값·경보 기준 같은 고정 조정값은 SARS-CoV-2 공개 평가 창으로 고른 값이다.
- 실제 다른 병원체 자료로는 검증하지 않았다(대회 자료에는 SARS-CoV-2만 있음).
- 새 병원체에서는 고정 조정값을 그대로 두고 성능을 먼저 확인할 것을 권한다.

## 11. 한계

예측 성능은 개선했지만, 남은 오류의 원인을 모두 규명했다고 주장하지 않습니다.

**아직 확인하지 못한 것**
- 유행 자체의 변화, 채취 처리장 구성 변화, 강수 희석의 효과를 서로 분리했음을 입증하지 못했습니다.
- 강수는 입력으로 활용했고 예측 기여도 확인했지만(7.4절, 주로 경보 쪽), 희석 신호를 복원해 t+2 농도 예측을 개선했음을 입증하지는 못했습니다. 강수의 영향이 없다는 뜻이 아니라, 현재의 공간 집계와 자료로는 그 기여를 분리하기 어렵다는 뜻입니다. 처리장 구성은 `n_sites`·`pop_sampled`로 추론한 '구성 변화 의심 신호'이고, 실제 채취 조합과 같다고 보장할 수 없습니다.
- Q1 취약 구간에는 결측과 구성 변화가 함께 나타났지만, 다른 요인을 배제하지 못했습니다(7.2절). 결측 행의 경보를 과거 같은 관측 조건의 실제 양성 비율로 보정하는 방법은 다음 버전 과제로 두었습니다.
- 주간 잡음이 크고, 2주 사이 3배 이상 급변(전체 행의 약 22%)이 오차의 약 41%를 차지합니다. t+1·t+3주 실측을 넣은 한 실험에서 점수가 약 0.40이었지만, 이것이 모든 방법의 상한이라는 뜻은 아닙니다.
- 경보는 실제 급증 비율보다 다소 많이 냅니다.

**일반화와 운영**
- 학습 이력이 1년 미만이면 기준 모델보다 약해서, 안전장치로 기준 모델 쪽으로 물러납니다.
- 평가 기간 이후의 성능과 실시간 공표 지연을 반영한 성능은 보장하지 않습니다. 하수-임상 선행성도 연관성에 대한 기술통계입니다.

**추가로 필요한 자료** (대회 제공 범위 밖, 향후 확장 제안): 주차별 실제 채취 처리장 목록과 시료 수, 처리장별 농도와 채취 시각, 하수 유량, 실제 집수구역 경계와 그에 맞춘 강수, 자료의 실제 공개 시점.
